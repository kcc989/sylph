# Run Project Repository git operations in the Worker and start Workspaces in the background

Sylph performs Project Repository git work (bootstrapping a blank repository, importing a GitHub Repository, and synchronizing an Upstream Repository) inside the Website Worker on an in-memory filesystem in `apps/web/src/server/project-repository-git.ts`, not inside a Workspace Durable Object. The Workspace Durable Object boots the whole OpenCode runtime before it can serve any request, so routing git-only work through it paid that cold start and cloned the Project Repository into Durable Object storage only to discard the clone during hydration. Upstream synchronization compares the remote heads first and clones only when they differ. Project and Workspace creation return as soon as the Project Repository head and the Workspace fork exist and record the Workspace as `provisioning`; runtime hydration, credential activation, and session creation continue through `waitUntil`, and the Workspace screen already reconciles `provisioning`, `ready`, and `error` from the runtime snapshot. Work that needs the durable Working copy or the agent session stays in the Durable Object.
