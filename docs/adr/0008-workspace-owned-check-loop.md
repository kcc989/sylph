# Optional Check repair uses the normal coding agent

Checks, Preview deployments, and browser evidence are separate requested operations. Saving a Checkpoint and synchronizing the Project Repository do not start them. The User can request automatic repair for a Check; it is disabled when omitted. A failed opted-in Check continues the normal coding agent with its diagnostics, while other results are recorded without starting another Turn.

The Workspace retains its three-continuation budget, durable inbox identity, acknowledgement handling, obsolete-commit suppression, and archived-Workspace protection. Production Deployments never enter this loop.

Acceptance requires a reviewed current Checkpoint, but no Check or Preview by default. Browser journeys constrain Acceptance only when the User configures requirements. Production recovery and verification are separately selected release capabilities; a requested data restore retains the complete recovery contract. These built-in capabilities are not user-defined event hooks.
