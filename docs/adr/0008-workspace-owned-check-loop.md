# The WorkspaceDO closes the Check loop and owns the repair policy

Cloudflare CI reports every Check state to the WorkspaceDO, records the run in the D1 `ci_runs` index, and stops there; the Durable Object decides what happens next. On a terminal result it sends one synthetic message to the OpenCode session (queued behind an active Turn, otherwise starting a new one) so the agent never has to poll, and it applies the resume policy itself: automatic repair is capped per Check and by a Workspace-wide budget that only a User prompt or a passing Check restores. Keeping the policy in the object rather than in the Workflow means duplicate CI callbacks, archived Workspaces, and repair limits are all enforced by the single writer of workspace state, and production deploys stay outside the agent's reach behind an Admin confirmation in Project settings.
