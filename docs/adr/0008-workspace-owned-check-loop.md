# Check completion resumes the normal coding agent

The WorkspaceDO owns a Check-completion hook: a failed Check automatically continues the normal coding agent with its diagnostics, while a passing Check records the result without starting another Turn. There is no separate repair command or repair state machine; the Workspace enforces a three-continuation budget across Checks, reset by a new User message or a passing Check, and production Deployments never enter this loop.

The Check result and pending Conversation message are recorded together. Delivery checks eligibility before atomically preparing the message and reserving its continuation budget; retries reuse that decision. An uncertain delivery retains its reservation because the agent may already have accepted it. Delivery uses a stable OpenCode inbox identity and remains pending until acknowledged; the Workspace alarm retries failures, and delivery to an archived Workspace or an obsolete Checkpoint is suppressed. The runtime queues results behind an active Turn and registers a wake whenever the continuation message is still pending, including while a Turn is settling, so retrying an acknowledged inbox admission does not start an extra Turn.
