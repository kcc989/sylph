# Domain schemas are the interface; codecs and failure envelopes stay at the seam

`@workspace/domain` exports schemas, ids, tagged failures, and the pure functions that belong to a concept, split by the CONTEXT.md vocabulary (Workspace, Project, Installation, Provider connection, Conversation, Check, and so on). It does not export one decode or encode constant per schema: a module that crosses an I/O seam declares the codec it needs next to its own imports with `Schema.decodeUnknownPromise` or `Schema.encodeSync`, so the domain interface stays as small as the set of schemas and a new schema never widens it twice. The Workspace runtime seam is one module, `apps/web/src/server/workspace-runtime-client.ts`, whose interface is the decoded domain types and whose only adapter in production is the Durable Object RPC stub; it is tested through a fake stub. Because Workers RPC preserves only an error's message, a tagged failure thrown inside the Durable Object crosses the hop as a `@sylph/failure:` envelope produced by `serializeServerFailure` and restored by `runtimeFailure` on the Worker side, so callers and the UI branch on the same tags whether the rule lived in middleware or in the Durable Object.
