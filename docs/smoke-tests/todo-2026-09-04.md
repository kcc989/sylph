## Reliability findings and local repairs

1. **Saved file approvals did not persist in practice.** The permission hook replaced existing allow and deny decisions with ask. The local fix preserves decisions and adds regression coverage.
2. **An older Check replaced the newer Check in the panel when it finished late.** Checks were ordered by last update. The local fix returns Checks in creation order and tests an older failure arriving after a newer run starts.
3. **Verification failures retried identical commands.** The SDK default allowed two retries with increasing delays. Typecheck, lint, test, and build now disable those inner retries. Install and deployment retries remain. Transient infrastructure failures in verification can still require a whole-Check retry. This change has not been timed live.
4. **Large file editing was unreliable.** Built-in local filesystem tools do not edit the durable Workspace. The agent eventually replaced `bun.lock` with only two dependency lines, removing roughly 1,650 lines. The local `workspace_edit_file` tool uses an exact unique match, preserves other content, reuses file-write permissions, and rejects stale or ambiguous edits. Tests cover a large file, literal replacement text, Unicode and line endings, persistence, deletion, invalid paths, binary content, and file size limits.
5. **Cancellation needed a reload to show completion.** After cancelling a stalled lookup, reload showed `Step interrupted` and resumed the queued message. Workspace content survived. The stale live cancellation display is not fixed here.
6. **Automatic repair was omitted.** Despite the initial natural-language request, the agent called Checks without `repairOnFailure: true`. Both observed Checks had repair disabled. Later steering explicitly supplied the parameter; no subsequent Check completed.

The local `workspace_restore_file` tool also restores one file from the latest Checkpoint using durable Git objects. A real SQLite filesystem/Git test recovers a large truncated file while preserving another file's uncommitted changes; it rejects Git metadata paths, traversal, and files absent from the Checkpoint.

All platform repairs remain local. Full local tests passed: 288 tests, zero failures. Lint, formatting, typecheck, and build passed. They have not been deployed to the live Installation.

The read-only `alchemy plan --stage prod` completed: three resources to update, six unchanged, none to create or delete. It lists Database, Website, WorkspaceRuntime, and their secret bindings as updates. No deployment was performed. The installed Alchemy `plan` command always uses dry-run mode and does not accept a separate `--dry-run` flag. The fetched `origin/main` still matches the starting revision.
