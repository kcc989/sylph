# Cloudflare agent lifecycle integration

This change combines the six E2E gap assignments into one Sylph branch. It adds the supported starter contract, D1 recovery, production observations and repair Workspaces, broader resource management, browser journey acceptance, and combined lifecycle/preservation tooling.

Implementation and live proof are separate. Starter `0.2.0` is published and pinned at `36860839fb2b1536228775998f3cce730f5b028c`. The combined lifecycle must still be exercised on a disposable Installation at the exact integrated commit.

## Integration checks

The final combined implementation at `635f28e` passed format, lint, all package/root typechecks, the full test command (617 tests), and the production build. The local Workerd runtime smoke and all 59 Storybook browser tests also passed. The starter candidate passed 28 tests, typecheck, lint, formatting, build, the shared platform contract verifier, full patch applicability, and copied recovery-source hash checks.

The Browser Run service fixture passed 74 ordered steps at exact source commit `71b118722d8dd5fc194e43f74ef494d3bd86ec82`, stage `smoke-browser-mtrwecsj`, with a clean source tree and recorded source hash. [Sanitized evidence](browser-service-smoke.json) lists the steps. It covered actual reconnect, blocked unconfigured popups, CRUD/D1 and session persistence, duplicate action receipts, failure/retry, desktop/mobile DOM assertions, stale attempts, human handoff, a separate OAuth fixture with state/code checks, interruption, blocked navigation, and session close. These are service-fixture results; the full Sylph product UI, a real identity provider, and the combined Installation lifecycle were not exercised.

Cloudflare's client alone reproduced screenshot capture timeout after freeze/resume. The successful fixture selected an explicit, audited DOM-only policy. The default screenshot policy still blocks acceptance when capture fails. DOM activation does not verify pointer hit targets or appearance. Disposable fixture stages remain retained; no cleanup was performed.

Integration regression fixes include CI filtering of recovery variables, flattened application secret snapshots, background health scheduling, distinct migration order, recovery source reconciliation, published commit/URL selection after failed releases, exact stateful backup coverage, private verification before writer resume and public verification after it, and monitoring/repair for failed publications without fabricating telemetry.

The approved starter branch was published and its remote hash verified before the immutable pin changed. No production release, application restore/undo, resource deletion, or earlier Installation migration was performed by the integration owner. Disposable browser-fixture evidence remains separate from combined product lifecycle proof.
