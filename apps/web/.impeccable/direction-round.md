# Sylph visual direction round

## Product mechanism

Sylph makes code, agent sessions, skills, browser preview, browser testing, and repository state facets of one durable remote Workspace.

## Scene and cultural home

The user is a developer checking sustained agent work throughout the day, often from a laptop, switching between intent, evidence, and the running product. The cultural home is operational craft: places where one person coordinates several live systems without losing the main event.

## Category rut

The expected page is a charcoal three-pane IDE with a file tree, editor, and chat rail. Its predictable opposite is an oversized empty chat canvas. Neither is in the grounded list.

## Grounded directions

1. Flight Strip Bay — air-traffic progress strips make parallel Workspaces tangible while the active strip unfolds into one continuous workbench.
2. Broadcast Vision Desk — preview and source monitors make the running product the program feed, with agent actions treated as controlled cuts.
3. Cartographer's Light Table — repository history is the base chart, Workspace changes are translucent overlays, and preview reveals the changed terrain.
4. Architectural Pin-Up — files, browser evidence, and diffs are working drawings arranged for critique around the live model.
5. Composing Room — code, conversation, and browser proof become galleys assembled into the next release edition.
6. Field Instrument Case — remote runs, tests, and deployments read as compact calibrated instruments surrounding the work surface.
7. Stage Manager's Prompt Desk — the live product owns the stage while the user and agent coordinate cues, scripts, checks, and interventions from one prompt book.

## Challenger verdicts

- HyperCard Stack: competitive. It strongly identifies with software making and makes browse/edit one object, but fixed cards weaken the simultaneous relationship between conversation, files, and live preview.
- Midnight Transit Diagram: competitive. It makes parallel Workspace paths and state transitions exceptionally clear, but developers identify less directly with passenger wayfinding than with a production desk.
- Nixie Laboratory Counter: declined. It makes state changes physical but overweights metrics and ornament relative to building the product.
- Iridescent Cloud Edge: declined. Its chromatic restraint is valuable, but uncertainty analysis does not map cleanly to routine software work.
- Sneaker Archive Wall: declined. Its reveal mechanics are strong, but a catalog of boxes makes Workspaces feel like inventory rather than live places.
- Streaming Title Wall: declined. Focus dimming is useful, but poster rails obscure code, causality, and review.

## Raises retained by the assigned direction

- From Nixie Laboratory Counter: every run and state transition gains a visible, localized change rather than ambient dashboard motion.
- From Iridescent Cloud Edge: color remains a narrow signal band around an otherwise disciplined neutral work surface.
- From Sneaker Archive Wall: the active Workspace physically advances while inactive Workspaces recede without disappearing.
- From Streaming Title Wall: focus quiets surrounding regions without removing their context.

## Re-roll 1

The first hand was rejected for making the Workspace feel like a themed control artifact. Every first-round direction and challenger is eliminated.

### Fresh grounded directions

1. Diff Proof Sheet — one continuous mixed file, diff, and browser-evidence scroll makes the change itself the organizing surface.
2. Tiled Workspace OS — a strict keyboard-driven window plane lets conversation, code, preview, and skills become rearrangeable Workspace objects.
3. Debugger Timeline — agent activity, browser actions, file edits, and checks form an inspectable causal trace around the live product.
4. CAD Model Space — the running product is the model; code, agent context, and checks are layers and inspectors attached to it.
5. Instrumented Preview — the live browser is the workspace ground, with code, diffs, agent actions, and test evidence anchored directly to regions and events in the product.
6. Live Specification — a precise product spec continuously pairs intent, implementation, and browser proof in one readable engineering document.
7. Storyboard Workspace — browser states are full working frames connected by agent actions, code changes, and test transitions.

### Fresh challenger verdicts

- Acetate Manual: competitive. Its layered transparency and tab rail make complex context unusually legible, but the manual voice can imply reference reading rather than live product manipulation.
- Cutting Bench: competitive. Its persistent position, marks, and reachable discarded work map well to an agent trace, but the single rail underrepresents simultaneous files and browser state.
- Metro Typographic Tiles: declined. Chrome deletion is valuable, but poster-scale type and tiles reduce the density engineering work needs.
- CRT Arcade Grid: declined. Its code-addressable state discipline is strong, but the game grammar misstates the seriousness of ordinary product work.
- Industrial Quote Grammar: declined. Literal labels are clear, but quotation marks, hazards, and tags become costume faster than system.
- Cyclorama Dawn: declined. Its focus and atmospheric phases are elegant, but light-state transitions do not explain code or causality.

### Raises retained by Instrumented Preview

- From Metro Typographic Tiles: delete chrome that does not carry an action or state.
- From CRT Arcade Grid: every browser and agent state remains addressable and inspectable in code.
- From Industrial Quote Grammar: labels stay literal and self-explanatory.
- From Cyclorama Dawn: inactive context recedes through value and depth rather than being removed.

## Re-roll 2 — safer register

The user established the missing quality with a Conductor screenshot: preserve the familiar dense IDE shell and its nested Repository → Workspace grouping in the left rail, but make Sylph more distinctive and more browser-first. Physical metaphors are no longer candidates.

### Familiar register

1. Browser-First Sylph — nested Repository/Workspace rail at left, live browser as the central work surface, agent thread at right, evidence tools below.
2. Thread-First Sylph — Conductor-like central agent narrative with a persistent live browser and change inspector sharing the right side.
3. Adaptive Split Sylph — nested left rail plus a large center that can shift between browser-dominant, agent-dominant, and true split modes without changing navigation.

The canon is a direct Conductor/bb/Diffs-adjacent dark three-pane IDE. It is included as the familiar baseline, not the recommendation.
