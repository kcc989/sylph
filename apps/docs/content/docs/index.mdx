Sylph gives people durable cloud Workspaces for coding agents. You deploy one
Installation into your own Cloudflare account, claim it, and invite your team.
Every part of the product — the interface, the source history, the build, the
preview, and the production deploy — runs on Cloudflare services.

## What "full stack on Cloudflare" means here

Most agent products keep the agent in a container and treat the cloud as a
deploy target. Sylph does the opposite. Each product concept maps onto the
Cloudflare primitive that fits it:

  <Card

  </Card>

## The shape of the product

An **Installation** is one deployment of Sylph. It is one security and data
boundary, and it contains one **Organization**. The Organization owns
**Projects**. A Project has one **Project Repository** and one or more
**Workspaces**.

A Workspace is where work happens. It holds an isolated fork of the Project
Repository, a live agent, and a durable Conversation. When the agent has
something to show, it writes a **Checkpoint**, runs a **Check** on that exact
commit, and deploys a **Preview**. You review the result and **Accept** it,
which merges the Checkpoint into the Project Repository.

<Callout title="Nothing is accepted on trust">
  A Checkpoint becomes acceptable only after a Check passes on that exact
  commit. Previews and browser Evidence are attached to the Check that produced
  them.
</Callout>
