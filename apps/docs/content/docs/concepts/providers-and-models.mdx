---
title: Providers and models
description: How model access is connected, shared, and overridden.
---

## Provider connection

A **Provider connection** is authorization for one AI provider together with the
models currently available through it.

| Scope                   | Owner            | Shared with |
| ----------------------- | ---------------- | ----------- |
| Organization connection | The Organization | Its members |
| Personal connection     | One User         | Nobody      |

An Admin manages Organization connections. Each User manages their own Personal
connections.

## Model preference

A **Model preference** is a preferred provider model chosen for an Organization
or for a User. A User preference overrides the Organization preference without
changing either Provider connection.

## Selection order

For the next agent Turn, the model is resolved in this order:

1. The [Conversation model selection](/docs/concepts/conversations-and-turns),
   when one is set.
2. The User's Model preference.
3. The Organization's Model preference.

Changing a selection never rewrites earlier turns. A Conversation keeps the
model that produced each past Turn in its record.

## Credentials

Provider credentials are encrypted with the Installation's credential
encryption key and stored in D1. They are never written into a Workspace
filesystem, a Conversation, a Check log, or an Artifacts repository.
